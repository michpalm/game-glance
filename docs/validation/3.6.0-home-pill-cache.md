# Home store and Family Sharing pill stability

2026-10-25. User reported that the store and Family Sharing pills flickered while switching games, unlike the other Home controls.

## Reproduction and cause

On the installed transition candidate, eight controller bumper switches created nine distinct `.gh-source` containers, removing the old container on every switch. The initial run recorded 15 blank rAF frames. A second run around Metro 2033 Redux (286690), which Steam reports has two available family copies, recorded 16 blank frames; its family pill was present for only 82 of that game's 89 visible frames.

Store lookup promises were already cached, but Home's `useAsync` returned undefined on each changed key, so the conditional containing all the pills unmounted until the promise completed. Even native Steam's already-known label followed this asynchronous path. Family copy counts had no per-game memo and reset to zero while every new selection asked Steam again. Store-version groups likewise had a cached raw catalog but no synchronous read for the selection render.

## Changes

- Native Steam store labels render synchronously. Resolved shortcut labels can be read synchronously; failed lookups still retry instead of freezing a guessed source.
- Family copy counts are cached by Steam account and app ID, with pending-query deduplication, a 30-second freshness window, and the last known count retained during refresh. Steam overview changes force refreshes. Labels still derive from live owner/persona data, not cached names.
- Store-version groups can be read synchronously from the last resolved Unifideck catalog, including while its existing 30-second refresh runs.
- Home's existing warm-up reads local store/family metadata nearest the current selection first. These local reads do not depend on the online pre-load setting. The generic `useAsync` hook is unchanged.
- No previous game's label or ownership is shown for an unknown game.
