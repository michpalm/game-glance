A preceding upgrade was confirmed before its cancellation check, so it was counted as an accepted upgrade instead.

The two original catalog cache entries were restored; the frontend was reloaded to discard the fixture's in-memory catalog. Test globals, duplicate panel, pending modals and loopback package server were removed.

## Confirmation-route investigation

An early report that the route bypassed confirmation was incorrect. The first logger matched install_plugin but missed confirm_plugin_install, and the dialog renders outside the inspected Big Picture document. Decky's registered `utilities/install_plugin` route delegates to request_plugin_install; the latter is a Python function, not a separately registered websocket route. The proposed route change was discarded and never installed. There is no updater source change.

Verified against Decky 3.3.0's [route registration and utility implementation](https://github.com/SteamDeckHomebrew/decky-loader/blob/v3.3.0/backend/decky_loader/utilities.py) and [request/confirm/cancel implementation](https://github.com/SteamDeckHomebrew/decky-loader/blob/v3.3.0/backend/decky_loader/browser.py), then confirmed through the actual device events and dialogs.

Local evidence: `out/roundtrip-3.5.0/results.json`, `upgrade-prompt.png`, `downgrade-prompt.png`, frontend test logs and the two explicitly local test ZIPs. Final frontend build hash remains `48fdcbdc1be98218fbdb81c4bd2f2f1cee856d15e2c5b9e1d1b6fcdb4d3667bf`.

Public GitHub catalog/asset acceptance, physical picker focus/scrolling and offline refresh remain separate checks. No publication was performed.
