# 3.5.0: unavailable-game explanations (#62)

2026-10-23. Included in the local 3.5 and 3.6 development worktrees; not installed or published by this change.

## Cause and fix

Issue: https://github.com/michpalm/game-glance/issues/62#issuecomment-6362313429

Steam renders its invalid-platform status (display_status 14, "Available for" plus platform icons) inside `StatusAndStats.PermanentlyUnavailable`. Game Glance hid the entire StatusAndStats wrapper to remove duplicate game statistics. This hiding rule originated in 9cb4599, included in v1.0.0.

Keep permanently unavailable status wrappers visible, while hiding ordinary status wrappers and duplicate GameStatsSection, Playtime and LastPlayed elements. If Steam's unavailable class cannot be resolved, avoid blanket-hiding its status wrapper. Steam retains control of the Install button and compatibility restrictions.

## Verification

- Regression tests first reproduced the hidden platform reason and missing-class fallback (four failures); all twelve new regression cases pass after the fix.
- 3.5: all 1,573 frontend tests pass; TypeScript and Rollup build pass.
- Ally, Steam's current renderer: off-screen synthetic invalid-platform input, no real game or compatibility setting changed. Old rule: message 0 x 0, wrapper display none. Fixed rule: message about 166 x 23 CSS px, wrapper display flex. Ordinary wrapper: still display none. Probe removed afterward.

## Remaining device acceptance

No game in the Ally library currently reports invalid-platform status. The reporter's exact compatibility setup and a complete end-to-end check with a genuinely blocked game remain unverified. No install, launch or compatibility setting was changed. The probe validates warning visibility, not a successful installation.
