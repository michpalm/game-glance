# Seamless transition follow-up

2026-10-23. User reports the current Clean transition looks worse, with a slow/doubled store pill and an information card that still compresses at handoff. This is an open visual regression; previous geometry checks did not establish seamlessness.

## Store pill: confirmed trajectory mismatch

The moving Home pill and destination-sized extras pill crossfade while the latter sits stationary at the destination. Recorded up to 10.1149 CSS px vertical separation while both were visibly contributing. The copied bridge and native page pill ultimately differ by only about 0.02 px, so the final landing coordinates alone miss this issue.

A device-only matched-path probe reduced the observed maximum vertical separation during overlap to 0.0121 CSS px. The local candidate adds a right-edge/top offset for the extras pill and transitions it with the same duration/easing as the Home pill. Bridge copies freeze at the destination. Missing Home pills use zero offset. Family content remains inside the same moving pill.

The local implementation passed all 1,677 tests, TypeScript, Rollup and whitespace checks. Two new regression assertions failed before implementation. This candidate has not been packaged or installed; the Ally remains on the preceding canvas-blur correction, `8098040`.

Evidence: `out/seamless-followup/` and `out/seamless-pill-probe/`, including traces and full-resolution screencast frames. The geometry numbers concern the temporary CSS probe; production-device acceptance remains outstanding.

## Information card: still unresolved

Confirmed original chip values are opacity zero once twins take over, including in the final bridge. The doubles are not caused by original chip values remaining fully visible under twins. Computed font sizes and Range bounds match the final native card, but glyph raster extents change slightly between live Home, frozen bridge and native page. The opaque bridge comparison also retains small ink differences. Consequently matching bounds and snapping glass edges are insufficient acceptance criteria.

A previous native-origin/centering probe did not resolve the text effect. A further individual-transform probe was inconclusive: the active game changed, so fixed text crop measurements were not comparable. No production card/text adjustment is included on that evidence. Further checks must pin the same app and compare text pixels as well as geometry through all three rendering stages.

Temporary recording/probe code is under `/tmp` and ignored `out/`; it is not part of the plugin. Do not describe the complete transition as fixed or regression-verified.

## Implemented shared Clean card (supersedes open findings above)

After the user approved reusing CleanInfo, extracted `CleanInfoPanel` and `cleanInfoCss` so Home's moving Clean card and the page use the same flex layout, text and rounded progress bars. Home receives the page-formatted Played/HLTB data and its existing achievement/size data. The panel is positioned by the Play row center and right inset; Chromium lays out the intrinsic card rather than predicting its content boxes. Its glass moves from the Home chip union, with inverse child transforms preserving the chip text/bar sizes at the start. Both panel and child transforms finish at the native layout. Missing-chip columns fade in without inheriting the panel's transform.

Clean no longer renders its content as independent text twins, scaled chip bars and a separate scaled glass/crisp-ring pair. Title, eyebrow and Play twins remain. Spotlight retains the prior card path. If the shared panel cannot be measured, the existing path remains available. Cancellation removes the added state and restores the panel's inline styles. The store-pill matched-path correction is included.
