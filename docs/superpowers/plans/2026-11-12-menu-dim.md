# The Game Glance menu's dim — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Game Glance menu gets the context menus' dim (38% `rgb(5,7,10)` + 6 px blur over the whole screen, under the menu's glass), on Home and over a game.

**Architecture:** One shared value (`MENU_DIM` in `src/styles/tokens.ts`) feeds the context menus' CSS, Home's frost and (mirrored in Python, checked by a test) the shader. On Home, `createHomeFrost` adds one full-screen dim surface before its area surfaces. Over a game, the ReShade effect blurs the whole scene at quarter resolution, dims it in `Composite`, weighted by the fade and the "present" flag, both read once per vertex.

**Tech Stack:** TypeScript (vitest + linkedom), Python (pytest), ReShade FX template, Decky.

**Spec:** `docs/superpowers/specs/2026-11-12-menu-dim-design.md`

## Global Constraints

- Dim: colour `rgb(5,7,10)` at alpha `.38` (CSS `rgba(5,7,10,.38)`); blur 6 canvas px (`6 × homeCanvas(w,h).scale` CSS px on Home; `sigma = 6 × dpr` output px in the shader, as `GLASS_BLUR_CSS_PX × dpr`).
- The dim sits **under** the menu's glass (before the area surfaces on Home; before the areas' blend in `Composite`) and **over** nothing of the menu's own drawing.
- The status pill and the button hints stay sharp.
- Never a CSS mask on a viewport-sized `backdrop-filter` (`src/menu/frost/home.ts`).
- Shader: no per-pixel read of the 1×1 state in the full-screen pass (cost ~20 ms a frame on the Ally): `fade` and `present` are read in `FadeVS` and passed `nointerpolation`. Texture formats only those Gamescope can create (`RGBA16F`, `RGBA32F`).
- The full-screen blur ships only if the menu-open frame time over a game is within **1 ms** of the dim-only build (Ally, handheld, one demanding game); else `DIM_BLUR = False` and the spec records the cost.
- Python tests: pytest is not installed system-wide; `$PY` = a scratchpad venv's python with pytest (`python3 -m venv <scratch>/pyenv && <scratch>/pyenv/bin/pip install pytest`). Baseline 2026-11-12: `tests/py/test_frost_shader.py` 36 passed.
- Shader changes need a **full restart** of the Ally. Never set `GAMESCOPE_RESHADE_EFFECT` by hand. CEF probes read-only.
- Commit only on Michael's word; identity `-c user.name="Michael Palma" -c user.email="18511803+michpalm@users.noreply.github.com"`, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. The menu closes (or hands off to a page) and the dim stays: Home's dim surface must go with `clear`/`dispose`; the shader's weight must reach 0 with every area empty (`present` = 0), not only through the fade.
2. Docked vs handheld: the blur follows Home's canvas scale on Home and `dpr` in the shader, so a TV and the Ally look alike.
3. A game letterboxed (`fit`) or below the display resolution: the shader's full-screen blur samples in output space through `InputUV`, so bars and the picture blur without seams.
4. The keyboard opening or closing re-applies Home's frost: the dim surface is kept, not recreated or reordered after the area surfaces.
5. The two values drifting: the context menus' CSS and the shader's constants are pinned to `MENU_DIM` by tests.
