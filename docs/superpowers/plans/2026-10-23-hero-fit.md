# Hero Art Fill and Fit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Hero art" setting with Fill (today) and Fit (the whole art at the top, fading into a blurred copy) on Home, the restyled game page (normal and Clean looks) and the open transition.

**Architecture:** One pure module (`home/heroFit.ts`) owns the mode type, the art-fill filter and the fade mask. Home draws Fit as two pseudo-element layers on its full-art hero; the page draws it on Steam's header image plus a fill layer under it, with the art url and mask passed as CSS variables by `GameHero`; the transition's other-game fade-in uses the same layers.

**Tech Stack:** TypeScript, React (Decky), CSS-in-TS (`homeCss.ts`, `themeCss.ts`), Vitest.

**Spec:** `docs/superpowers/specs/2026-10-23-hero-fit-design.md`

## Global Constraints

- `Settings.heroFit: 'fill' | 'fit'`, default `'fill'`; anything else reads as `'fill'`.
- Copy: setting label **Hero art**; options **Fill** — "Fills the screen; the sides of wide art are cut off." — and **Fit** — "Shows the whole art at the top, with a blurred copy behind it."
- Art fill filter (VDL `art-fill`): `blur(42px) saturate(1.25) brightness(.8)`; the fill layer extends past its box (inset −120 px) so blurred edges stay off screen.
- Fade: the last 22% of the art's extent next to the fill (`FIT_FADE = 0.22`).
- Fit anchors the art at the top centre, fitted inside the box (`contain`).
- Unchanged: Fill everywhere; the screensaver; the 1.1.1 page output (Spotlight Home off) stays byte-identical; Home's fallback hero (`.gh-hero-blur` + `.gh-hero-sharp`).
- On the page, Fit replaces the restyle's `${topCapsule} img { object-position: 50% 30% !important }`; a weaker rule beside it leaves the art 138 px low.
- Commits use the noreply identity copied from `git log -1 --format='%an <%ae>'`; no push.

## Review Focus

1. Art whose size is not known yet (still loading, or the other game's hero during a fade-in): Fit uses a standard 3.1:1 mask until the real size is known; never no mask (a hard edge) and never Fill's framing.
2. Changing the setting while Home or a page is open: the hero changes at once, without reopening.
3. Custom art taller than the screen's shape (SteamGridDB heroes): whole art centred horizontally, both side edges fading; not cropped.
4. A 16:10 screen (the Deck): the fade ends at 51.61% of the height for 3.1:1 art; nothing assumes 16:9.
5. Leaving the page: the variables `GameHero` set on the page's document are removed, so another page or the 1.1.1 look never sees a stale art url.

- [ ] **Step 1: Write the failing tests**

```ts
it('reads fill and fit, anything else as fill', () => {
    expect(heroFitOf('fit')).toBe('fit');
    for (const v of ['fill', 'whole', undefined, null, 3]) expect(heroFitOf(v)).toBe('fill');
});
it('wide art: the bottom 22% of the art fades (16:9 and 16:10)', () => {
    expect(fitMask(3.1, 16 / 9)).toBe('linear-gradient(180deg, #000 44.73%, transparent 57.35%)');
    expect(fitMask(3.1, 16 / 10)).toBe('linear-gradient(180deg, #000 40.26%, transparent 51.61%)');
});
it('tall art: centred, both sides fade', () => {
    expect(fitMask(1, 16 / 9)).toBe('linear-gradient(90deg, transparent 21.88%, #000 34.25%, #000 65.75%, transparent 78.12%)');
});
it('art the shape of the box needs no fade; unusable sizes use the standard hero shape', () => {
    expect(fitMask(16 / 9, 16 / 9)).toBe('none');
    expect(fitMask(NaN, 16 / 9)).toBe(fitMask(STANDARD_HERO_ASPECT, 16 / 9));
    expect(fitMask(0, 16 / 9)).toBe(fitMask(STANDARD_HERO_ASPECT, 16 / 9));
});
```
