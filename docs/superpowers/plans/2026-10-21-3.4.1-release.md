## Review Focus

- **B pressed after Steam has navigated** (the cancel listener is already gone): `onCancelled` must not fire, and no sound or return fade may play over the page. Pinned in Task 1 (test "no cancel hook once the page has opened").
- **Home's root gone or disconnected** when the cancel fires (Steam unmounted Home): `showCancelReturn` does nothing and never throws. Pinned in Task 1.
- **Two cancels within the fade** (B, A, B quickly): the second must replay the fade, not leave the attribute stuck. Pinned in Task 1 ("a second cancel restarts the fade").
- **Steam's sound player not found** (another Steam build): the cancel still restores Home. `playNavSound` already swallows this; Task 1's homeNav step calls it inside the hook after `finish`, so nothing depends on it.
- **Lutris database locked or mid-write** (Lutris is running and saving play time): the read fails or finds nothing, and Game Glance keeps Steam's number, never an error and never 0. Pinned in Task 4 ("an unreadable database").
- **Both a Flatpak and a native Lutris installed** (their game ids are independent): a Flatpak shortcut must read the Flatpak database only. Pinned in Task 4 ("the shortcut's install decides the database").
- **A feed-card open (`heroFade` variant) cancelled:** the other game's hero snaps back to Home's hero (the return fade never touches the hero, by design). This is a known limit and is not fixed in 3.4.1. Task 6 records it as a checklist row so Michael judges it on device.
